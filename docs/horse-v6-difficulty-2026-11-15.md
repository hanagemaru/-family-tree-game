# 競走馬血統ならべ v6：難易度再調整（2026-11-15）

## 結論

初級・中級・上級を**すべて12頭・最大4世代・初期配置1頭**に固定したまま、出題される馬の知名度だけを引き上げる方針を採用。

| 難易度 | v5の選定条件 | v6の選定条件 |
| --- | --- | --- |
| 初級 | 知名度上位15%（131頭）から12頭 | **上位10%（88頭）から12頭** |
| 中級 | 高知名度馬4〜6頭を目標 | **高知名度馬6〜8頭を目標** |
| 上級 | 高知名度馬1〜3頭を目標 | **高知名度馬3〜5頭を目標** |

「高知名度」は凍結した知名度ランキングの上位35%を指す。順位はWikimediaページ閲覧数・JRA顕彰馬・データ内で把握できる産駒数から算出した相対値であり、実際に誰もが知っていることを保証するものではない。

中級・上級の頭数範囲は**生成時に目標として強く優遇する条件**。配列の整合性・手札から実際に完走できること・カードの非重複・線の整合性を優先し、最悪の場合には目標から外れる可能性がある。問題頭数そのものは常に12頭。

## 実装

- 新しい出題生成器 `horse-stage-v6` を使用。初級の候補フィルターを10%に変更
- 中級・上級はv6専用の目標値を設定し、抽出時の重みおよび候補評価に反映
- 従来のv5出題ロジック・難易度目標は凍結し、以前の12頭問題のセーブを再現できるようにする
- 端末に旧v5問題が残っているときは「変更前の12頭問題を再開」を表示。18頭版も旧モードとして維持
- 旧v5の端末内自己ベスト（`v5:<difficulty>`）と新v6（`v6:<difficulty>`）を混在させない
- 公開ランキングのバージョンは `horse-score-v2-v6-12x4`。サーバーはv6に対応し、初級12頭の全員が上位10%であることを検査。旧v5の記録は新ランキングに登録不可
- **ヒント10秒、誤回答15秒、自動配置45秒という採点ルールは変更しない**
- 変更はPR #13上のみ。本番Cloudflare Worker・DBとハブサイトには未公開

## 実データ100シード×3難易度で検証

使用データ：`wikidata-pedigree-v1`（名前のある872頭）、知名度スナップショットの期間終了日 `2026-10-31`。各難易度につき`v6-benchmark-1`〜`v6-benchmark-100`の固定シードを使用。各シードで候補96回を作成し、実際の盤面レイアウト・手札配布・全カード完走を実行して採否を判定。

| 指標 | 初級 | 中級 | 上級 |
| --- | ---: | ---: | ---: |
| 生成成功 | **100/100** | **100/100** | **100/100** |
| 新しい知名度条件に適合 | **100/100** | **100/100** | **100/100** |
| 配置・血統・盤面の整合性合格 | **100/100** | **100/100** | **100/100** |
| 100問中異なる馬の組み合わせ | 98 | 94 | 100 |
| 高知名度馬の平均頭数 | 12.00 | 7.55 | 4.63 |
| 世代数3/4 | 2 / 98 | 0 / 100 | 2 / 98 |
| 初級に登場した馬の知名度平均順位 | **31.12位 / 872頭** | — | — |

- 中級の分布：高知名度6頭×10問、7頭×25問、8頭×65問
- 上級の分布：高知名度3頭×5問、4頭×27問、5頭×68問
- 対照実験として同じ初めの25シードでv5も生成。v5の高知名度馬の平均は**中級5.84頭、上級2.88頭**。v6はそれぞれ約1.7〜1.8頭増えた
- 厳密には「問題が毎回必ず知名度目標に収まる」ことを100サンプルだけでは保証しない。失敗時のフォールバック・例外検出は従来どおり残す

検証ワークフロー：[Horse v6 difficulty 100-seed benchmark](https://github.com/hanagemaru/-family-tree-game/actions/runs/43686306197)

実測スクリプト：`scripts/benchmark-horse-v6.mjs`（`node scripts/benchmark-horse-v6.mjs 100`）。ワークフローのArtifactに機械集計JSONを保管。
